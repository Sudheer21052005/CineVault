# CineVault upgrade plan

27 November 2026 · `feature/ui-redesign`

Start with a behavior-preserving foundation. Establish storage compatibility, eliminate the reproducible navigation and search failures, and measure the existing flows before changing screen composition. Then build the responsive browsing experience and expand it with linkable cinema metadata and a richer personal library. The [baseline audit](BASELINE_AUDIT.md) records the original findings and TMDB inventory, and [Phase 1 results](PHASE1_RESULTS.md) records the implementation, measurements and verified platform coverage.

## Product scope and invariants

- CineVault is a discovery, reference and personal watchlist app. Use the existing name, emblem, blue and gold palette, and developer credit for **Sudheer Prajapati** in the README and an in-app About screen. Keep posters, recommendations and viewing availability tied to their sources.
- Preserve Home feeds, Now Playing, TV browse, title search, discovery filters, overview/runtime/TV totals, similar and recommended titles, save/edit/remove, statuses, diary fields, charts, activity and achievements. Their entry points may move if each remains readily reachable and covered by a regression flow.
- Preserve Hive record keys, boxes, adapter, values, package/bundle IDs and the deployed web origin where possible. Any future storage or deployment change that needs a migration must carry existing records forward. New features work with local storage on every supported platform and stay usable when TMDB is unavailable.
- Maintain Flutter Web, Android, iOS, Windows, macOS and Linux. Plan native release checks, platform-specific shortcuts, browser URLs, and touch navigation. Phase 0 changes only documentation.

## Architecture and ownership

Use feature modules with narrow public APIs and keep Provider as dependency injection and view-state glue through the first migration. Extract behind existing screens in small changes. Introduce packages only after a selected dependency proves cross-platform support and reduces maintenance. Evaluate a maintained Router-based package such as `go_router` against a prototype for browser history, nested branch state, native deep links and observer hooks. [Flutter navigation guidance](https://docs.flutter.dev/ui/navigation)

| Module | Owns |
| --- | --- |
| `app` | Bootstrap, dependency composition, route parsing/serialization, shell, app settings and platform policies. Initialize the catalogue and library independently so a failing box or credential can surface its own recoverable state. |
| `core/design` | Theme extensions and component variants for artwork, cards, lists, rails, filters, page headers and loading/empty/error/offline states. |
| `core/network` and `core/cache` | Instance-scoped TMDB transport, credentials, request scheduler, error mapping, metrics, response caching and image policy. Expose clocks and transport interfaces for deterministic tests. No global mutable client/cache shared between repository instances. |
| `catalogue` | TMDB DTOs and mappers, read repositories, typed IDs, summaries, detail/credit entities, localized labels and relationship queries. Own normalized merge rules and source field provenance. |
| `discovery` and `search` | Feed definitions, facet schemas, pagination and query controllers, dedupe, ranking, search scopes and explanation text. Widgets consume state snapshots and send commands. |
| `titles`, `people`, and `explore` | Presentation and controllers for Title, Person/Filmography, Collection, Studio, Network, Genre, Keyword, Season and Episode. Related cards route through the shared application contract instead of creating other feature widgets directly. |
| `library` and `statistics` | Hive-backed library repository, private ratings/reviews/notes, diary, custom lists, progress and statistics. Compute selectors from committed snapshots. The library stores a compact title snapshot for offline use. |

Use immutable screen states such as loading, ready, refreshing, empty and recoverable error with explicit initial versus next-page state. Widgets can retain local focus, text editing and animation state. Controllers own `load`, `refresh`, `loadNext` and disposal. They receive immutable query snapshots and guard results by generation so a stale request cannot update current state. Use narrow provider selectors for saved state and statistics. Repositories return typed errors, keep prior successful content during refresh and expose per-section failures. Scope instances per route or loaded branch and construct async work outside `build`.

### Entity and relationship model

- Use `EntityRef(kind, tmdbId)` for globally addressed entities within their namespaces. Use media-kind-scoped `GenreRef`, and composite routes for `SeasonRef(seriesId, seasonNumber)` and `EpisodeRef(seriesId, seasonNumber, episodeNumber)`. Keep season 0 valid. Separate entity summaries from full detail and preserve known fields when a lower-detail card arrives later.
- A credit preserves the source credit identifier, person/title references, character or job, department, order and episode counts if supplied. Group by person/title at presentation time with multiple visible roles and jobs. Use IDs instead of display-name matching for all relationship links.
- Treat edges as typed references backed by a TMDB detail field or a repository query. A title links to cast and crew, production companies, collection membership where present, genres, keywords, related titles and TV seasons. Person links to filmography by role and type. Studio, network, genre and keyword link to filtered title catalogues. Season links to series and episodes, and episode links to parent season, series, neighboring episodes and credited people. A watchlist entry links to its title via the same reference.
- Keep link destinations discoverable when only part of a page loads. Disable or omit controls for missing relation IDs, keep loading and failed sections recoverable, and distinguish a genuinely empty section from unavailable metadata. Handle 404 with a route-level state and a return path. Apply stable sorts to paged results and suppress duplicate IDs without collapsing distinct roles. Infinite exploration consists of durable links and back history. Bound resident pages, caches and prefetch irrespective of how long somebody explores.

### Hive compatibility and personal data

Keep `cinevault_watchlist`, `cinevault_achievements`, `typeId = 1`, the positional prefix, existing optional tails, status strings and `movie-<id>` / `tv-<id>` keys in the first migration. Keep the adapter registered in one place. Initialize once, read existing items before deriving achievements, and distinguish empty libraries from opt-in samples. Preserve existing sample records because they occupy the same schema as user records and may have been edited. Write through a repository that permits null clears explicitly, sequences overlapping mutations per key, publishes only after successful item writes, and reconciles idempotent achievement updates after interruptions. Use indexed reads by key and lazy list presentation.

Add separate versioned boxes for new viewing events, custom lists and episode progress so existing boxes remain readable by older builds. Preserve the single legacy watched date as existing history, give any backfilled event a stable source identifier, and dedupe it on retries. Leave existing date strings/epochs and achievement IDs intact. A new version can layer additional achievements or compute corrections without revoking recorded unlocks. Define timezone rules for display and viewing-day grouping. Test legacy short records, records with each optional tail, current writes, missing artwork, same numeric movie/TV IDs, nullable fields, duplicate/racing writes, failed writes, close/reopen and release builds over a copy of previous data. Keep backups or exports before later migration, with a documented forward and rollback check. Cloud sync or TMDB account linking requires a separate opt-in decision and data ownership design.

## Responsive navigation

Use the same destination hierarchy across layouts. Proposed top-level destinations are Home, Discover, Search and Library. Discover exposes Movies, TV and Now Playing, and Library exposes Watchlist, Diary, Lists and Stats as they ship. Home retains direct entry to major featured shelves and a visible Search affordance. Keep Statistics reachable from Library in one additional action, with routes stable across viewport changes.

| Logical width | Layout and input |
| --- | --- |
| Below 600 px | Four-label bottom navigation with safe areas. Use a compact app bar, touch rails, a filter sheet and one-column detail sections. Use two poster columns only where the actual cell width supports consistent artwork and truncation. |
| 600–1023 px | Compact navigation rail, roomier grids, and a modal or inline filter surface according to space. Preserve the same four destinations and branch state. |
| 1024 px and above | Persistent labeled sidebar and top search affordance, centered page body, optional browse filter panel and two-column detail when content fits. Constrain long prose to roughly 65–75 characters per line and keep shelves aligned to the shared page gutters. |

Measure breakpoints by available logical width after insets, with initial verification at 320, 390, 599, 600, 768, 1023, 1024 and 1440 px. Retain scroll, filters, result page and selected destination across size/orientation changes. Focus rings, keyboard traversal, Enter/Space activation, Escape to dismiss and desktop search shortcut should follow platform expectations. Support visible rail buttons, touch swipes and trackpad/pointer scrolling. Apply Android system Back at the root and normal browser/desktop history semantics. A reselected destination may return to its branch root, with a clear behavior for preserving the user's current scroll.

Use canonical paths such as `/discover/now-playing`, `/search?q=Inception&scope=movie`, `/movie/27205`, `/tv/1396/season/1`, `/tv/1396/season/1/episode/1`, `/person/525/filmography`, `/collection/:id`, `/company/:id`, `/network/:id`, `/genre/:mediaKind/:id`, `/keyword/:id`, and `/library/watchlist`. Resolve routes from IDs even on direct open without an in-memory card. Use independent lazily mounted branch stacks and serializable filter state. Push user-selected routes, restore last list scroll/focus on back, and avoid duplicating the current route for repeated taps. When a deep link has no in-app predecessor, the back affordance returns to the parent or the appropriate branch. Web hosting must support the chosen URL strategy and reload of entity routes. Never serialize private notes or reviews in routes. [Flutter adaptive design](https://docs.flutter.dev/ui/adaptive-responsive) · [Flutter navigation](https://docs.flutter.dev/ui/navigation)

## Design system

Use the existing [`CineVault Cinema Design System`](../stitch_cinevault_cinema_tracker/cinevault_design_system.md) as the design input and bind its tokens to Flutter components. Preserve near-black `#0B0D12`, tiered `#121722`/`#192131` surfaces, electric-blue actions and muted-gold ratings. Define semantic text, surface, border, focus, disabled, action, success, warning and error pairs for use on both canvas and artwork. Validate actual rendered contrast, especially text on primary buttons and hero scrims. Use a 4/8 px spacing scale, standard compact/wide gutters, consistent corner radii and a single hierarchy for page title, section title, metadata and body. Check licensed/bundled Poppins and the reference's Spline Sans Mono or define explicit system fallbacks. Subset fonts where possible, and verify long text and locale coverage.

- Standardize 2:3 posters and profiles, 16:9 backdrops and episode stills. Preserve layout with missing, loading and failed images. Use component variants for hero, rail, grid and library row. Align metadata and badges, and use a distinct missing rating label. Use fewer image effects in grids and remove redundant headings and directions.
- Make cards and metadata edges discoverable with explicit focus, hover, pressed and selected states. Use meaningful labels for icon actions such as `Filter results`, `Clear search` and `Remove Inception`. Announce loading or error at the relevant region with retry. Add prose or numeric summaries for charts and accessible labels for activity cells. Present distinct labels for the TMDB score and private half-star rating.
- Use a common feedback pattern for saving and removing with visible completion or undo, plus form-level recovery for failed writes. Design search and discovery filters with visible applied facets and clear/reset controls.
- Honor system reduced motion. Pause carousel when backgrounded or obscured and allow deliberate navigation with keyboard and touch. Load ambient color asynchronously from a small image after the first useful paint, if profiling justifies the effect. Define 44–48 logical px interaction targets. Test 200% text scaling, 4.5:1 normal text contrast, 3:1 large text and key control indicators, visible keyboard focus, and screen-reader order. [WCAG 2.2 quick reference](https://www.w3.org/WAI/WCAG22/quickref/)

## Discovery and ranking

1. **Text search.** Use multi search for All and keep TMDB relevance on the initial listing. Render distinct movie, TV and person results. Movie/TV/People scopes use the relevant typed search endpoint with supported parameters. Collection, Studio and Keyword can use opt-in separate scopes. Resolve recognized external IDs via Find. Keep the adult-content default explicit and consistent across catalogue requests, avoid merging paginations with unrelated shapes, and preserve title queries across scope changes. Debounce typing initially around 250–350 ms and issue immediate search on submission. Invalidate request generation at input change, clear or mode switch, reset paging atomically, and coalesce duplicate submissions.
2. **Faceted browse.** Use movie/TV Discover with typed facet definitions, capability validation and canonical URLs. Support genre, year/range, rating and vote floor, language, market, keyword and companies, with movie credit/person and TV network filters where supported. Provide field-specific AND/OR options only when documented. Provide independent visitable genre and keyword pages. Text search exposes constraints it can enforce using its active endpoint. Group advanced discovery behind its own mode so every visible filter describes the actual query. Use explicit regional release types for regional rails. Choose one upstream source per paginated feed after the first page, so falling back cannot mix cursors from two feeds.
3. **Related exploration.** Prefer TMDB recommendation and similarity lanes as separate, source-labeled feeds. Add explicitly labeled object edges for a collection, filmmaker, network, studio, shared genre or keyword. Keep true relation edges deterministic and context-bearing. Use on-demand expansion of results and a small context panel on wide screens if it preserves keyboard and reading order.
4. **Personalized suggestions.** Start with up to three recently watched/high-rated seeds, cap calls, remove existing library/hidden titles, and diversify media and genres while maintaining stable ties. Combine TMDB recommendation order, repeated seed matches and chosen affinity signals. Show a reason grounded in input, such as “Similar to Inception,” and fall back to editorial or trending feeds when private data or matches are unavailable. Treat watched/ratings/notes as local. Event or telemetry payloads exclude private user content, and user controls can opt out or clear history. Compare recommendation quality using fixture-based relevance and diversity checks before exposing more signals.

Record request, retry, cached hit and no-result counts by named operation, and scope any analytics to consented, redacted signals. Never count an empty mixed page after local filtering as a hard end when a valid next cursor remains. Provide visible next-page error and retry, and keep results on screen when that retry fails. [TMDB finding data](https://developer.themoviedb.org/docs/finding-data) · [Movie Discover](https://developer.themoviedb.org/reference/discover-movie) · [TV Discover](https://developer.themoviedb.org/reference/discover-tv)

## Network, cache and artwork

| Layer | Proposed policy to validate |
| --- | --- |
| Request identity | Normalize operation, typed entity, page, sorted query/section keys, effective language and meaningful market. Preserve order where an operator or field gives it meaning. Exclude credentials from cache keys, URLs in logs, diagnostics and metrics. Use one in-flight request per key with bounded concurrency initially at four JSON requests. Prioritize user actions, then visible sections, then near-viewport prefetch. Drop obsolete queued requests and discard stale results when transport cancellation is unavailable. |
| Retry and degradation | Distinguish connectivity, timeout, 429, 4xx, service errors and malformed data. Honor `Retry-After` when present, use jittered exponential backoff and a shared cooldown for 429, and cap attempts plus the total interactive wait budget. Do not retry authentication/validation errors or a deterministic parse failure. Show stale content with age/offline indication when appropriate. Retry section queries with a fresh request operation. Use narrowly scoped invalidation and prevent pre-refresh in-flight writes from resurrecting invalidated entries. [TMDB rate limiting](https://developer.themoviedb.org/docs/rate-limiting) |
| Memory and durable metadata | Start with an LRU of at most 150 response entries or 12 MiB per app instance, with telemetry to tune. Use a separately versioned, evictable store for durable metadata, initially capped at 40 MiB native and 15 MiB web if supported by the platform and terms. Never evict private library data as catalogue cache pressure rises. Treat quota, eviction and disabled browser storage as cache misses. Clear catalogue cache independently. Store metadata source, locale, fetched time and schema version for recovery and testing. |
| Freshness | Starting fresh TTLs are configuration/dictionaries seven days, stable title/person metadata 24 hours, release/trending rails 15–30 minutes, search results five minutes in memory and availability by market six hours. Allow bounded stale reuse when permitted by current TMDB terms, with stale-while-revalidate and independent per-section timestamps. Revalidate on explicit refresh. Never show old availability as current without age context. |
| Image sizing | Derive secure CDN base and named size variants from `/configuration`; choose the smallest available variant that meets logical display size times a capped device pixel ratio. Use native decode-size hints when supported and use server-delivered sizes for web. Retain one decoded variant at a time where practical. Decode/prefetch the leading hero and immediate visible/next rail items within budget, and defer palette generation, galleries and offscreen assets. Use browser HTTP caching on web and evaluate a bounded platform-supported file cache for native only where load tests warrant it. [Configuration](https://developer.themoviedb.org/reference/configuration-details) · [Image basics](https://developer.themoviedb.org/docs/image-basics) |

Render a summary immediately. Add only the small, above-the-fold sections to the initial details request when `append_to_response` reduces the actual byte and latency budget on representative fixtures. Load large related pages, videos, galleries, reviews and providers on demand with independent status. Measure both request count and body bytes before enabling another append. Replace nested grids with one lazy sliver viewport per page, use input-appropriate rail controls, and remove idle work on inactive branches. Use catalogue timeouts and installation recovery UI so local features can load independently. [Append to Response](https://developer.themoviedb.org/docs/append-to-response)

Keep the ignored dotenv flow for development. Before distributing a build with a private production credential, use an approved gateway or another reviewed production access model, because a Flutter client cannot protect an embedded secret. A gateway, if selected, should enforce supported catalogue routes and parameters, cache and rate-limit them, avoid storing user library data, and redact requests. Check current TMDB terms for cache retention and distribution, confirm the license for any commercial use, and show the approved TMDB logo and required notice in About/Credits with CineVault's identity more prominent. Add JustWatch attribution on provider surfaces. [Application authentication](https://developer.themoviedb.org/docs/authentication-application) · [TMDB attribution and licensing](https://developer.themoviedb.org/docs/faq) · [Watch provider rules](https://developer.themoviedb.org/reference/movie-watch-providers)

## Measurement and regression gates

Baseline on a named Windows/Chromium desktop build and a representative physical Android profile build. Add an iOS and Safari smoke run, and native release smoke builds for all supported targets. Keep the SDK, viewport, DPR, device refresh rate, fixture revision and network conditions with results. Use reproducible mocked/staged payloads for app timing comparisons, including a normal `~350 ms` response delay and an offline or 429 scenario. Record external TMDB samples independently because the service and catalogue vary. Capture at least 30 samples for p50/p95 per interactive scenario, with cold process and cleared catalogue/image cache runs distinct from warm re-entry. Record fixture sizes (e.g. 20, 200 and 1,000 titles plus a long series), first frame, usable shell, first useful image, route summary, search result marker, request count/bytes, and UI/raster frame durations, memory and failed frames during a repeatable scroll. Use masked route names and omit raw URLs, private queries, tokens and library data. [Flutter UI profiling](https://docs.flutter.dev/perf/ui-performance) · [Flutter web profiling](https://docs.flutter.dev/perf/web-performance)

Proposed release budgets below are acceptance targets under that controlled fixture protocol. Lock the exact hardware and harness before tuning. These targets do not describe the current debug-web measurements.

| Scenario | Target |
| --- | --- |
| Startup | Usable shell p95 ≤ 2.0 s cold with local library initialized or a recoverable library state. Warm p95 ≤ 750 ms. Shell interaction has no fixed branding delay. Initial Home uses ≤ 4 JSON requests before its first useful viewport and zero requests exclusively for inactive branches. |
| Images and scrolling | First visible hero or poster painted p95 ≤ 2.8 s from cold launch. No network duplicate for the same in-flight size variant. At 60 Hz, ≤ 5% of frames exceed 16.7 ms in the fixed 20-second scroll fixture, and no title or scroll position jumps after image load. Compare peak memory from cold through five paginated pages and a return to Home, and confirm response/image caches honor configured caps. |
| Search | Input to interactive first result p95 ≤ 1.2 s with the controlled 350 ms transport including debounce. One latest-query request for a burst of rapid typing, zero stale commits, and one request per page after retry dedupe. |
| Navigation | Warm card activation to visible detail summary p95 ≤ 300 ms and browser back/forward restores the last results and selected card. Fresh detail uses ≤ 2 interactive JSON requests before the summary/initial sections are useful. |
| Fault tolerance | For injected offline, timeout, invalid credentials, 404 and 429, catalogue shows a recoverable state while local watchlist remains readable/editable. No secret in logs, traces, commits or production app bundles. |
