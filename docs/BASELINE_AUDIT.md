# CineVault baseline audit

27 November 2026 · `feature/ui-redesign` · baseline `7d9440c3a3bcd749eea890d616ebb00f2d17622a`

This document records pre-implementation behavior. See [Phase 1 results](PHASE1_RESULTS.md) for fixes, verification and the controlled release-web comparison.

The existing Flutter Web app loads live TMDB data and supports local watchlist tracking. The highest-priority defects are a Now Playing back action that can leave a blank app, search filters that are ignored with typed queries, and a persistence initialization sequence that seeds an intentionally empty box and initially misses eligible achievements. Start with regression coverage, navigation and search correctness, and measurable data and storage boundaries. The [upgrade plan](UPGRADE_PLAN.md) defines the implementation sequence.

## Scope and repository verification

- Read all application Dart sources and the existing test suite, the dependency manifest and lockfile diff, platform runner and release settings, README, branding references, and the existing design system. Used source inspection for routes, storage and error paths, and a live Chrome-based Flutter Web session for screenshots and interaction checks.
- `origin` fetch and push point to [`nascent-sky/CineVault`](https://github.com/nascent-sky/CineVault). `upstream` fetch and push point to [`Sudheer21052005/CineVault`](https://github.com/Sudheer21052005/CineVault). The GitHub API confirmed the fork relationship and `git ls-remote` showed `origin/main` at the baseline above. `feature/ui-redesign` was checked out locally without a tracking branch or matching branch on `origin` at verification time.
- The starting worktree had an existing local `pubspec.lock` change and seven modified generated desktop plugin files. The lockfile has transitive resolution and SDK-floor changes. Git normalized the generated-file diffs away under its line-ending rules. Benchmarks and checks use the local resolved dependencies, and the documentation commit targets only these two Markdown files.
- `.env` is ignored, untracked, and absent from reachable local history under that path. `.env.example` is tracked. Live traffic used the configured key only with TMDB, and the recorded measurements contain endpoint paths without query credentials. The README credits **Sudheer Prajapati** and links to the original developer's GitHub profile. The app uses the CineVault name and `assets/images/branding/cinevault_emblem.svg`.

### Models and persistence

- `lib/models/media.dart` combines movie/TV cards and detail payloads with a string media kind, integer ID and `type-id` equality key at call sites. The parser keeps names from detail `genres` but discards list `genre_ids`. It flattens TV into season/episode totals and the first runtime, drops cast, credits, related IDs, providers and images other than the primary poster/backdrop, and uses `0.0` for missing ratings. Mixed types and unexpected payload values have weak validation.
- `cinevault_watchlist` stores `WatchlistItem` with adapter `typeId = 1` under `movie-<id>` or `tv-<id>`. Its positional prefix is ID, type, title, poster, TMDB rating, status name, nullable personal rating, notes, and added-at milliseconds. Optional positional tails are review, genres and watched-at milliseconds, read when bytes remain. `cinevault_achievements` stores string achievement IDs under auto-generated keys. The developer attribution and native package/bundle IDs are separate from Hive data, and deployment URL origin matters for access to existing browser storage.
- On every launch with an empty watchlist, initialization inserts eight demonstration entries. It calls `_refreshAchievements()` before loading `_items`, so a fresh sample library initially displays qualifying activity with locked achievements. Existing nonempty libraries skip that startup refresh. Provider methods mutate shared records before the write resolves, reload the entire collection, and scan for existing entries and achievement rules. Concurrent operations and a failure between the item write and achievement write have no explicit recovery contract. Failed Hive open can prevent startup. Browser storage is origin-scoped and subject to browser lifecycle. There is no export/import, repeat-viewing event model, user list, or episode-progress store.

### Dependencies and platform coverage

- Flutter/Dart with Material widgets. `provider` owns watchlist notifications, `hive`/`hive_flutter` own local storage, `http` and `flutter_dotenv` handle TMDB requests and configuration, `fl_chart` renders statistics, `flutter_svg` renders the identity mark, and `palette_generator` samples artwork. `cupertino_icons` is declared with no direct import in the application sources. `flutter_test` and `flutter_lints` support the existing checks. No dedicated router, image disk cache, test fixtures for TMDB or Hive, or CI workflow is tracked. The manifest declares Dart `^3.13.7`. On Flutter `3.50.1` and Dart `3.14.0`, `flutter test --no-pub --reporter expanded` passed all six tests. `flutter analyze --no-pub` exited 1 with two `deprecated_member_use` infos for `package:flutter/material.dart`, at `lib/app.dart:4` and `lib/main.dart:1`, under this installed SDK. Tests cover parsing, key separation, status fallback, diary fields in memory and end-of-page logic. They do not round-trip a Hive box or drive navigation and search.
- Android, iOS, macOS, Windows, Linux and Web runners are present. Android's main manifest lacks `INTERNET`; debug and profile overlays contain it. The inspected desktop macOS entitlement files lack `com.apple.security.network.client`, and Android release uses debug signing. The web manifest and HTML descriptions still use Flutter template copy and the web manifest requests portrait orientation. Treat these as source findings requiring packaged release verification. The audit exercised Flutter Web on Windows. Native binaries, physical mobile, persistence across installation upgrades and app-store packaging were outside the measured environment. The local Android device discovery failed because the ADB daemon could not be reached.
- `pubspec.yaml` bundles `.env` as an asset and `TmdbService` sends the key as a URL parameter. The distributed client asset can expose the key, and the cache key holds the full query URI. Keep log, test and trace output allowlisted and distinguish local developer setup from a production credential design. There is no in-app TMDB notice or approved TMDB logo in the source reviewed. [TMDB authentication and attribution](https://developer.themoviedb.org/docs/faq)

`TmdbService` currently applies successful-response caching for five minutes and coalesces by full request URL. Expired entries are only ignored, with no eviction or persistence. It retries 429, server errors, transient transport failures, and some parse errors up to three attempts, with 300/600 ms delays and 15 s per attempt. TMDB documents a variable defensive limit and asks clients to respect 429. Rate-limit and access errors should retain their type, and a prolonged failure should leave local data and eligible stale metadata accessible. [TMDB rate limiting](https://developer.themoviedb.org/docs/rate-limiting)
